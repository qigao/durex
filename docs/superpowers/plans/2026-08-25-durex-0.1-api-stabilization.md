# Durex 0.1 Public API Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the already-tested Durex Maven artifact surface into a deliberate, compatibility-checked, releaseable 0.1 public runtime platform.

**Architecture:** SimpleDSL remains build-time only. Durex owns four external Maven artifacts and an explicit type manifest that separates supported API from public runtime implementation. Compatibility and release verification operate on staged Maven artifacts, never project/source injection.

**Tech Stack:** Java 25, Gradle 9.1, SimpleDSL 0.1.1, Maven Publish, GitHub Actions, JDK `javap`, Spring Boot 4.1.

**Spec:** GitHub tracker #173 and issues #168-#172.

## Global Constraints

- Keep the external artifact set fixed to `shared-common`, `shared-spring-http`, `messaging-api`, and `messaging-spring-redis` during this phase.
- All PR verification must consume SimpleDSL through the Plugin Portal and public runtime artifacts through staged Maven coordinates.
- Do not require release credentials or signing secrets in normal PR CI.
- Do not freeze public implementation classes as supported user API merely because framework mechanics require public visibility.
