= Durex
:icons: font

Durex is a multi-module Java platform for Spring Boot development.

== Build Platform

The root build consumes SimpleDSL `0.2.0` from the Gradle Plugin Portal:

* `io.github.qigao.simpledsl.settings` owns dependency policy loading, module discovery, and project inclusion.
* Production modules apply only `io.github.qigao.simpledsl.build`; module types and capabilities are selected through `simpledsl { ... }`.
* Repository-root `dependencies.toml` is auto-discovered by SimpleDSL 0.2 and includes the Durex-owned dependency fragments under `dependencies/*.toml`; no explicit dependency-manifest override is used.
* Dependency policy uses the SimpleDSL 0.2 manifest contract: `[simpledsl] java`, Gradle-shaped `versions` / `libraries` / `plugins`, and BOMs declared as normal libraries.
* `gradle/modules.toml` contains only logical-name/build-file overrides; ordinary modules are auto-discovered.
* `build.spring.gradle` is the canonical Spring module descriptor.
* Gradle 9.1 and Java 25 are the current build baseline.

Useful diagnostics:

[source,bash]
----
./gradlew simpledslProjects
./gradlew simpledslDependencies
----

== Repository Gate

Every pull request receives one always-present `Durex Gate` check. It aggregates all other pull-request workflows actually triggered for the same exact head SHA and succeeds only after every discovered sibling workflow has completed successfully. Path-filtered workflows therefore remain efficient without becoming permanently pending required checks when their paths do not match.

After the workflow is merged, repository protection should require `Durex Gate` on `master` and disallow force pushes.

== Runtime

Spring Boot is the only application runtime. Durex adds runtime libraries and semantic adapters while SimpleDSL owns build-time composition.

* shared HTTP service contracts for server/client reuse
* Spring AOP and transaction integration
* Spring-native Redis Pub/Sub and Redis Streams messaging
* GraalVM native/AOT reference build

== Public Maven Surface

Durex publishes only deliberate runtime/API modules. The artifact group is `io.github.qigao.durex`; the 0.1 line is protected by an explicit type manifest plus a staged-Maven JVM signature baseline.

* `shared-common`
* `shared-spring-http`
* `messaging-api`
* `messaging-spring-redis`

Music, schema/codegen, migration, reference, and `shared-utils` modules are not part of the public Maven surface.

See xref:docs/public-artifacts.md[Public artifacts and Maven-only examples], xref:docs/public-api-lifecycle.md[Public API lifecycle and deprecation policy], and xref:docs/releasing.md[Release procedure].

== Schema

Schema/code generation remains build-time and framework-neutral. Durex activates jOOQ and JSON Schema generation through the public SimpleDSL project DSL:

[source,groovy]
----
simpledsl {
    jooqSchema()
    // or jsonSchema()
}
----

Generator configuration continues through `simpledslJooq` and `simpledslJsonSchema`. Durex does not carry a separate JSON Schema annotator runtime and does not reference SimpleDSL schema implementation classes.

See xref:core/shared/messaging/README.md[Spring Messaging].
